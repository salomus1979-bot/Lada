# Лада

Сервис онлайн-записи студии маникюра и оформления бровей: клиент сам выбирает
услуги, мастера и свободное время, а потом переносит или отменяет визит в
личном кабинете — без звонков и переписки.

В репозитории три слоя:

| Что | Где | Состояние |
|---|---|---|
| **API** — Express поверх SQLite | [`api/`](api/README.md) | готов, 302 сквозные проверки проходят |
| **Клиентский интерфейс** — обычные HTML, CSS и JS | [`web/`](web/README.md) | собран целиком, 19 экранов |
| **Раздел администратора** | `web/pages/admin` | **следующая итерация** — пока каркас без данных |
| Прототип из Claude Design | `*.dc.html` в корне, 46 файлов | образец, не меняется |

## Запуск

Нужен Node 22.5 или новее. Две команды в разных окнах:

```bash
npm start
```

```bash
npm run web
```

API поднимется на `http://localhost:3001`, интерфейс — на
`http://localhost:4000`. Перед первым запуском нужен `.env` (образец —
[`.env.example`](.env.example)) и наполнение базы демо-данными:

```bash
npm run seed
```

Сквозной прогон API — `npm run smoke`. Подробности про порты и прокси — в
[web/README.md](web/README.md).

## Клиентский интерфейс

Девятнадцать экранов прототипа, собранных вручную: без сборщиков и
фреймворков, один экран прототипа — одна страница в `web/pages`. Все
обращения к серверу идут через `web/js/api.js`, выбор в воронке записи — через
`web/js/store.js`, цвета, шрифты и размеры — только из `web/tokens.css`,
собранного из дизайн-системы.

| Раздел | Экраны |
|---|---|
| Витрина | лендинг, каталог услуг и прайс |
| Авторизация | вход, регистрация, восстановление пароля, новый пароль |
| Запись | шаг 1 «Услуги», шаг 2 «Мастер», шаг 3 «Дата и время», шаг 4 «Подтверждение», «Запись создана», «Время занято» |
| Личный кабинет | предстоящие записи, пустое состояние, детали записи и отмена, перенос записи, история, уведомления, профиль |

Что из этого работает не полностью и почему — разобрано в
[web/README.md](web/README.md), раздел «Чего ещё нет»: восстановление пароля
без эндпоинтов, уведомления без таблицы уведомлений, профиль только с блоком
активных сессий. Решения по каждой нехватке данных записаны в
[docs/ui-map.md](docs/ui-map.md), а правило «не хватает данных — скажи, а не
выдумывай обход» — в [docs/frontend-rules.md](docs/frontend-rules.md).

Интерфейс рассчитан и на телефон: раскладка складывается в одну колонку,
меню сворачивается, ничего при этом не прячется — на узком экране доступно
всё то же, что на широком.

Сессия живёт в HttpOnly-куке, которую ставит сервер. Страницы её не читают и
не хранят ни токенов, ни паролей.

## Раздел администратора — следующая итерация

Сейчас от него есть каркас: сайдбар, шапка и три пустые страницы («Записи»,
«Услуги», «Мастера»), плюс проверка роли на двух рубежах — в API
(`requireRole`) и в дев-сервере (guard на `/admin`). Данными страницы ещё не
наполнены, и экраны мастера (35–42 в прототипе) не начинались. Карта этих
экранов с эндпоинтами уже написана — [docs/ui-map-staff.md](docs/ui-map-staff.md).
