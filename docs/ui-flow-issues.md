# Прототип «Лада»: переходы, которые ведут не туда

Разбор мест, где переход **формально работает**, но по смыслу экрана ведёт не
туда, куда ожидаешь. Такие места опаснее мёртвых ссылок: мёртвая ссылка видна
сразу, а рабочий переход «не туда» спокойно уезжает в вёрстку как есть.

Собрано 18.10.2026 сплошным проходом по всем 46 файлам `*.dc.html`: для каждого
экрана выписаны объявления `const goToX = () => { window.location.href = … }`,
их привязки `onClick="{{ goToX }}"`, обработчики внутри данных
(`navItems[].onClick`, `bl.onClick`, `groups[].action`) и обычные
`<a href="…dc.html">`.

Отправная точка — [«Инвентаризация страниц.md»](../Инвентаризация%20страниц.md).
Список известных случаев из неё дополнен; две его строки оказались неточными —
см. [«Поправки к инвентаризации»](#поправки-к-инвентаризации).

- **[Починено](#починено)** — намерение однозначно, переход исправлен и прокликан.
- **[На решение владельца продукта](#на-решение-владельца-продукта)** — переход
  защитим в текущем виде или требует экрана/логики, которых в прототипе нет.

---

## Починено

Правки сделаны тем же приёмом, что принят в проекте: на страницах с блоком
`DCLogic` — привязка `onClick="{{ goToX }}"` к функции, объявленной в
`renderVals()` и возвращённой в `return {…}`. Новых скриптов не заводили.

| Экран | Элемент | Вело | Ведёт теперь | Почему |
|---|---|---|---|---|
| `24. Админ - Новая запись за клиента` | «Создать запись» | 22. Сетка расписания | 23. Записи | Две кнопки одной формы расходились: «Отмена» и крестик вели на 23, главная кнопка — на 22. Модалка нарисована поверх затемнённого списка записей, созданная запись появляется в нём же |
| `30. Админ - График работы мастера` | «Сохранить» в модалке исключения | 28. Мастера | остаётся на 30, модалка закрывается (`closeModal`) | Сохранение исключения — действие внутри графика, уход в список мастеров терял контекст. Самоссылка здесь не годится: модалка открыта по умолчанию (`state = { modalOpen: true }`) и после перезагрузки открылась бы снова |
| `34. Админ - Запросы мастеров` | «Подтвердить отмену» | 21. Дашборд дня | 34. Запросы мастеров | Обработка запроса не повод уходить с экрана: в списке остаются другие запросы |
| `34. Админ - Запросы мастеров` | «Отклонить запрос» | 21. Дашборд дня | 34. Запросы мастеров | То же |
| `34. Админ - Запросы мастеров` | «Отклонить» (запрос на изменение карточки) | 29. Карточка мастера (форма) | 34. Запросы мастеров | Отклонённое изменение карточку не меняет — открывать её незачем |
| `17. Кабинет - Уведомления` | строка «Пароль изменён» | 9. Детали записи и отмена | 16. Кабинет - Профиль | Уведомление о безопасности вело в карточку визита: у всех уведомлений в данных стоял один `action: goToDetails`. Блок смены пароля живёт на 16 |
| `6. Ошибка - время занято` | «Подтвердить новое время» | 4. Запись - Шаг 4 | 5. Запись создана | Подтверждение нового слота — финальное действие, а не возврат к сводке. **Кнопка осталась `disabled`** (демо-состояние «слот не выбран»); при вёрстке становится активной после выбора слота, и тогда ветка проходится до конца |

Проверено в браузере (`preview_start`, конфиг `prototype`): экраны 6, 17, 24, 30,
34 открываются без ошибок в консоли и без `sc-logic-error`, мёртвых `onClick`
нет. Прокликаны 34 → 34 («Подтвердить отмену», «Отклонить»), 24 → 23 («Создать
запись»), 30 («Сохранить» закрывает модалку, адрес не меняется), 17 → 16
(«Пароль изменён»). На 6 кнопка `disabled`, поэтому проверена привязка: её
обработчик — функция с переходом на `5. Запись создана`.

На 30 отдельно проверено, что страница рисуется целиком (сайдбар, график,
список исключений) — то есть дубля `const`, который валил этот экран раньше, не
появилось.

## На решение владельца продукта

Здесь переход либо защитим в текущем виде, либо требует экрана, которого нет.
Менять вслепую нельзя — выбор меняет сценарий.

### Авторизация и выход

| Экран | Элемент | Ведёт сейчас | По смыслу | Вопрос |

### Рядом: кнопки, которые не ведут никуда

Это не «ведёт не туда», а «не ведёт вообще» — полный список в инвентаризации,
[«Ссылки-заглушки»](../Инвентаризация%20страниц.md#2-ссылки-заглушки-и-несуществующие-страницы).
При вёрстке их легко спутать с рабочими, поэтому три самых заметных:

- `28. Админ - Мастера`, «Отмена» в модалке архивации — обработчика нет, модалка
  показана статично и не закрывается.
- `38. Мастер - Детали визита` — кнопки статуса, «Запросить отмену» и весь
  нижний шит («Отмена», «Отправить запрос») без обработчиков.
- `29. Админ - Карточка мастера`, «Принять» / «Отклонить» в блоке модерации —
  без обработчиков, хотя такие же кнопки на `34` работают.

## Поправки к инвентаризации

Две строки инвентаризации не совпали с кодом; исправлены в ней же.

| Экран | Было в инвентаризации | На самом деле |
|---|---|---|
| `7. Кабинет - Предстоящие записи` | «Перенести» и «Отменить» — локально (`transferClick` / `cancelClick`) | Оба перехода: `const transferClick = stop(goToReschedule)` → `10. Перенос записи`, `const cancelClick = stop(goToDetails)` → `9. Детали записи`. `stop` только гасит всплытие клика по карточке |
| `11. Кабинет - История записей` | «Повторить запись» — локально (`repeatClick`) | Переход: `const repeatClick = stop(goToBooking)` → `1. Запись - Шаг 1` |
| `21. Админ - Дашборд дня` | «Клиент не пришёл» — кнопка смены статуса визита | Карточка-алерт в блоке «Требует внимания», кнопок статуса на дашборде нет |
| `6. Ошибка - время занято` | «Подтвердить новое время» → 4. Шаг 4 | Переход теперь на `5. Запись создана`, но кнопка `disabled="{{ true }}"` — в прототипе не нажимается |
